## 🎯 1. Концепция и архитектура реализации

В соответствии с техническим заданием и ролевой моделью системы, интерфейс разделен на **3 независимых веб-приложения (сайта)**, работающих изолированно на разных портах. Это обеспечивает строгое разделение прав доступа: соискатели не имеют доступа к конфиденциальным данным оценки, рекрутеры оценивают ответы вслепую, а руководитель видит итоговую сводку и выносит решение.

| Порт | Компонент системы | Роль и назначение |
| :---: | :--- | :--- |
| **8501** | **`frontend_candidate`** | **Портал Кандидата (+ Демо-песочница)**:<br>• Вход по токен-ссылке.<br>• Прослушивание голосового приветствия (`TTS`).<br>• Согласие на обработку ПДн по 152-ФЗ.<br>• Прохождение интервью: озвучка вопросов, запись ответа в микрофон или загрузка файла.<br>• Вкладка «Демо-генератор» для создания тестового кандидата и вакансии в 1 клик. |
| **8502** | **`frontend_hr`** | **Кабинет HR-специалиста**:<br>• Мониторинг всех откликов с фильтрами по статусам.<br>• **Слепое независимое оценивание**: просмотр текстовых расшифровок ответов соискателя **без подсказок ИИ**, что исключает человеческую предвзятость.<br>• Выставление балльной оценки (от 1 до 10) и текстовой характеристики.<br>• Инициация автогенерации сводного отчёта `.docx` для ЛПР. |
| **8503** | **`frontend_lpr`** | **Кабинет ЛПР (Руководителя / Нанимающего менеджера)**:<br>• Сопоставление двух независимых оценок: балл ИИ (`AI_score`) и балл HR (`HR_score`).<br>• Просмотр заключения языковой модели (`LLM Summary`) и комментария рекрутера.<br>• Скачивание сформированного Word-отчёта (`.docx`).<br>• Вынесение резолюции: *«Пригласить на 2-й этап»* или *«Отказ»* с автоотправкой обратной связи.<br>• Архив ранее принятых решений. |

## 📁 2. Созданные файлы и модули

### 2.1. Исходный код Frontend (`services/frontend/`)

* **`app/candidate_app.py`** — точка входа для Сайта Кандидата (порт `8501`). Содержит навигацию между экраном интервью и тестовым генератором.
* **`app/hr_app.py`** — точка входа для Кабинета HR (порт `8502`).
* **`app/lpr_app.py`** — точка входа для Кабинета ЛПР (порт `8503`).
* **`app/main.py`** — диспетчер запуска: автоматически выбирает нужный портал на основе переменной окружения `APP_MODE`.
* **`app/api_client.py`** — клиент HTTP-запросов к `API Gateway`:
  * Инкапсулирует вызовы к сессиям кандидата, транскриптам, сохранению оценок и выгрузке `.docx`.
  * Реализует декодирование голосовых файлов из `base64` в бинарный формат для `st.audio`.
  * Обрабатывает сетевые ошибки и таймауты.
* **`app/views/candidate.py`** — экран кандидата с прогресс-баром, плеером вопросов, виджетом записи с микрофона (`st.audio_input`) и кнопкой финализации.
* **`app/views/hr.py`** — экран рекрутера со сводной таблицей, детальным просмотром расшифровок и формой выставления оценки.
* **`app/views/lpr.py`** — экран руководителя со сравнительными метриками, кнопкой скачивания Word-файла и вкладкой архива решений.
* **`app/views/demo.py`** — демо-панель: диагностика связи с сервером и генерация тестового отклика в 1 клик.

### 2.2. Конфигурация Docker и скрипты запуска Windows

* **`services/frontend/Dockerfile`** — образ на базе `python:3.11-slim`, оптимизированный для запуска Streamlit, с healthcheck-проверкой.
* **`services/frontend/.dockerignore`** — исключение временных файлов (`.venv`, кэш, git).
* **`services/frontend/requirements.txt`** — зависимости: `streamlit>=1.32.0`, `requests>=2.31.0`, `pandas>=2.0.0`.
* **`services/frontend/run_all_frontends.bat`** — скрипт Windows для одновременного запуска всех 3 сайтов в отдельных окнах.
* **`services/frontend/run_candidate.bat`** — локальный запуск Сайта Кандидата (`8501`).
* **`services/frontend/run_hr.bat`** — локальный запуск Кабинета HR (`8502`).
* **`services/frontend/run_lpr.bat`** — локальный запуск Кабинета ЛПР (`8503`).
* **`services/frontend/README.md`** — документация фронтенд-модуля.

## 🔧 3. Доработки и исправления в Backend-части

Для интеграции фронтенда потребовалось доработать несколько ключевых мест бэкенда:

### 3.1. `docker-compose.yml`
* Одиночный контейнер `frontend` заменён на 3 независимых сервиса:
  * `hrscreening_frontend_candidate` (порт `8501`)
  * `hrscreening_frontend_hr` (порт `8502`)
  * `hrscreening_frontend_lpr` (порт `8503`)
* Настроена сеть, проброс портов и переменные связи со шлюзом `GATEWAY_URL: http://api_gateway:8000`.

### 3.2. `services/api_gateway/app/routers/screening.py`
* Добавлен эндпоинт **`GET /api/v1/screening/responses`** — получение списка всех откликов для личных кабинетов HR и руководителя (ранее в API отсутствовал метод просмотра списка).
* Добавлен эндпоинт **`GET /api/v1/screening/{response_id}/result`** — получение полного результата с оценками обеих сторон (для ЛПР).
* Добавлен эндпоинт **`POST /api/v1/screening/demo-seed`** — генерация тестового кандидата, вакансии и пула вопросов.

### 3.3. `services/api_gateway/app/clients/db_client.py`
* Реализован метод **`get_responses(skip, limit)`** для выгрузки откликов из `db_connector`.
* Реализован метод **`create_demo_data()`** с корректной обработкой связей сущностей в PostgreSQL.

### 3.4. `services/api_gateway/app/routers/candidate.py`
* **Исправлена блокировка 403 Forbidden:** исходная реализация разрешала вход только в статусе `Ожидание скрининга`, из-за чего при согласии на ПДн статус менялся на `Процесс скрининга`, и кандидат мгновенно блокировался при перезагрузке страницы. Теперь эндпоинт корректно поддерживает активную сессию опроса.

## 🐛 4. Устранённые ошибки в процессе тестирования

1. **`ModuleNotFoundError: No module named 'app'`**  
   * *Причина:* Streamlit при запуске из подпапки добавлял в `sys.path` только текущую директорию.  
   * *Решение:* Внедрена автоматическая регистрация родительских директорий в `sys.path` и fallback-импорты.
2. **`ForeignKeyViolation: Key (position_id)=(1) is not present in table positions` (Ошибка 500)**  
   * *Причина:* `db_connector` не имел маршрутов для создания должностей, а внешний ключ блокировал создание пула вопросов с `id=1`.  
   * *Решение:* Пул вопросов и вакансия адаптированы под создание с опциональными внешними ключами (`None`), что позволило генерировать тестовые данные без сбоев.
3. **`TypeError: got an unexpected keyword argument 'rows'`**  
   * *Причина:* В виджете `st.text_area` использовался неподдерживаемый аргумент `rows=4`.  
   * *Решение:* Заменён на стандартный `height=120`.
4. **Пустая вкладка «Архив решений» у ЛПР**  
   * *Причина:* В блоке соседней вкладки стоял досрочный `return`, прерывавший отрисовку всей страницы.  
   * *Решение:* Логика переписана на независимые блоки условий; добавлен интерактивный просмотр и скачивание `.docx` для архивных соискателей.

## 🚀 5. Инструкция по запуску

### Запуск через Docker Compose (рекомендуется):
```bash
docker compose up -d
```
Сайты будут доступны по адресам:
* Кандидат + Демо: **http://localhost:8501**
* HR-специалист: **http://localhost:8502**
* Руководитель (ЛПР): **http://localhost:8503**

### Локальный запуск на Windows (без Docker):
Запустить двойным кликом файл:
```text
services\frontend\run_all_frontends.bat
```
*(Все три сайта откроются автоматически в отдельных окнах).*
